# AI辅助编码平台

Python开发的通用人工编码与局域网协作平台。第一阶段**不调用AI**，无需模型密钥，可完成材料导入、编码本、独立编码、分歧协商、信度报告、最终导出和项目归档。

当前为第一阶段可试用版。支持多人在同一项目中工作，但不是多人同时改写同一段原文的文档编辑器：独立编码各人分别保存，共享规则和协商结论检查保存版本。浏览器基本操作已用虚构数据验收；真实第二台电脑联网及更大并发仍需验证。

第一次使用可先看 [快速上手](docs/快速上手.md)。不想先安排任务时，可看 [快速开始、进度与历史修改](docs/快速开始与编码历史.md)。测试范围和未完成项在 [验收说明](docs/验收说明.md)。

## 你现在怎样打开

1. 在VS Code中打开本文件所在的 `ai-coding-platform` 文件夹。
2. 双击 `start.cmd`，或在VS Code终端运行 `.\start.cmd`。不要重复启动已运行的服务。
3. 浏览器打开 `http://127.0.0.1:8000`。
4. 首次账号默认 `owner`，随机初始密码在 `runtime/首次登录信息.txt`，首次登录必须更换。程序不会重置已有账号。
5. 查看页面中的“操作指南”。创建项目、导入示例、设置代码，再用邀请码邀请成员。不要把示例定义直接当作自己的研究规则。

服务电脑需要保持开机且不休眠。启动窗口中按Ctrl+C可以停止。若服务在后台运行，双击 `stop.cmd`，按提示输入STOP，只停止当前目录记录的8000端口服务；不会删除数据库。停止前请通知成员确认保存。

后台使用进程实例锁，拒绝同一目录、同一端口重复启动，并先检查端口是否已有服务。`runtime/server_端口.lock` 文件保留是正常现象，不要在服务运行时删除；进程退出会自动释放锁。锁采用Python官方的 [Windows文件锁](https://docs.python.org/3/library/msvcrt.html#msvcrt.locking) 或 [Unix文件锁](https://docs.python.org/3/library/fcntl.html#fcntl.flock)，不依赖修改防火墙。

## 新电脑安装

需要Python 3.12或3.13。运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\start.cmd
```

无需在其他成员电脑安装Python或VS Code。VS Code调试配置需要微软Python/Python Debugger扩展；没有扩展也能在终端运行。`runserver`仅用于开发，实际启动脚本使用Waitress。

## 局域网多人使用

在Windows设置中查明服务电脑的**可信局域网IPv4地址**，例如 `192.168.1.20`。在服务电脑运行：

```powershell
.\start.cmd --host 192.168.1.20
```

上述IP仅示例。成员通过 `http://服务电脑实际IP:8000` 登录。服务仅监听明确的LAN地址及本机地址，不开放数据库端口，也不配置公网映射。

也可复制 `.env.example` 为 `.env`，设置 `PLATFORM_HOST` 和 `PLATFORM_ALLOWED_HOSTS`，以后双击启动。网络或IP变化后须更新这两项并重启。PowerShell脚本仍可选用，但不需要为运行平台修改系统执行策略。

若同伴打不开：确认两台电脑在同一可互通网络、无访客隔离、主机未休眠、IP未变，以及防火墙是否允许此应用端口。**不要关闭整个防火墙**。若需新增规则，应由使用者确认，仅允许专用网络和本地子网。平台不自动更改系统安全设置。

局域网HTTP不是加密连接：仅适合受控网络试用；正式敏感材料应由技术人员配置可信HTTPS反向代理，再设置 `PLATFORM_HTTPS=1`。不要在未配置HTTPS前打开该选项。

## 已实现的人工流程

- 项目各自的研究目标、成员、权限、代码、标签模式和任意导入附加列。不固定学生、AI、实验条件或小组。
- CSV（UTF-8/GB18030）、单工作表XLSX、TXT导入和字段预览。8MB/10000行每批；原始字节保留，文件重复导入拦截，空白行保留但不生成单元。TXT按行导入；XLS需先另存为XLSX。
- 意义单元切分、相邻合并、排除及原文定位；调整只影响未来轮次，已有任务的单元不变。
- 代码层级、定义、纳入/排除、正反例、边界例、共现和优先规则。冻结版本不可编辑，修改需复制新版本。
- 编码本文件导入：XLSX、CSV、TSV、DOCX、TXT、Markdown、JSON及带明确规则字段的文字型PDF；常见表头自动对应，通常只需上传、检查预览、确认导入。没有名称列时沿用原代码文字；不明确的表头需人工选择，其他设置默认折叠。工作表选择、层级校验、来源留档和旧版本保护保留。详见[导入编码本与自定义导出](docs/导入编码本与自定义导出.md)。
- 培训、独立试编码、正式编码轮次；随机/均衡分层抽样、固定种子、全员同批/单人分工/部分双人复核。
- 可选的开始方式：负责人和编码员都能为本人“快速开始”，不填写任务安排表；多人分工、抽样或独立一致性评估仍用“安排编码任务”。快速开始固定所选规则版本和当前全部有效单元，重复点击会继续原来的未完成批次，不给别人分配任务。
- 编码进度：总条数、已提交、已保存草稿、尚未开始、各批次提交比例；每10秒更新汇总及本页。负责人和复核者另可查看成员数量汇总，不公开他人答案。
- 我的编码历史：按最后保存时间筛选，支持今天、近7天、近30天及北京时间分钟范围；快速关键词搜索、完整匹配及编号/规则/批次等组合条件。草稿直达原工作台修改，个人快速批次的已提交记录需说明理由后退回；保留每次保存的旧答案，归档只读。
- 选填单元编号，指定再次试编码的样本池。抽样池、实际抽样编号和曾公开讨论的单元均留档；旧单元已拆分或排除时禁止重新分配。
- 工作台上下文、主代码/次代码、疑点、无适用代码、中文或英文备注；个人草稿自动保存；提交后锁定。个人快速编码可从历史入口说明理由后退回修改，多人任务仍须负责人或复核者退回。
- 提交前不提供他人答案、汇总标签、讨论或全量答案导出；全部提交后进入协商。
- 保存版本检查、原子事务、个人答案隔离、重放请求防重复、修改历史。协商最终结果不覆盖独立编码。
- 每页统一返回入口，按当前账号、当前浏览器标签页记录最近访问页面；保留搜索与分页条件。直接打开时返回项目或工作空间。未确认保存的编码会阻止按钮跳转，不自动提交或覆盖答案。
- 分歧与疑点清单：筛选标签差异、不确定、尚未定稿；识别主次互换，跳转指定单元并导出CSV。系统不自动判断语义原因。
- 标签集合、主代码、次代码分别比较；单标签配对Cohen’s κ、名义类别Krippendorff’s α、多标签逐代码二元比较。一级维度依据显式父子关系，不猜测代码前缀。报告保留输入版本、层级快照和抽样来源提示，不自动判断研究质量。
- 导出中心：材料、规则、本人/全员判断、分歧、最终结果支持XLSX、CSV、TSV、JSON，编码本另支持DOCX；可选择字段、改列名、调整顺序、设置CSV编码和分隔符。项目ZIP归档保留，含讨论、日志及已确认编码本导入原件。CSV/TSV与Excel防止原文被执行为公式。
- 成员自行注册、邀请码申请加入项目小组、负责人审核并分配权限、撤回与重新申请；保留负责人直接添加成员的方式。
- 账号密码验证、初始账号强制改密、CSRF、项目权限、安全响应头、单进程登录／注册／申请限流、在线数据库备份。

第一阶段暂不做AI、原始材料PDF/OCR直接导入、多人逐字改写原始正文、无限量导入、自动判断编码质量或置信区间。编码本的文字型PDF需要明确字段，复杂表格或扫描件仍需转换。重新开放过答案的轮次不再视为盲法；新的独立评估必须建立新轮次。

## 自己注册，然后加入小组

一个编码项目就是一个小组，不另外建立与项目重复的小组结构。

1. 成员在登录页点击“创建自己的账号”，填写用户名、密码及确认密码。无需邮箱或手机号；成功后自动登录。自己设置的密码不需要再强制更换一次。
2. 负责人进入项目的“项目成员”，生成邀请码，选择1、7或30天有效期，把平台的局域网地址和邀请码私下提供给同伴。
3. 成员登录后点击“加入小组”，输入邀请码及选填的申请说明。在“我的项目”查看状态。等待审核时不能进入项目或查看材料与答案。
4. 负责人在“待审核的加入申请”核对身份，同意或拒绝。默认权限为编码员，可选复核者或只读成员，不能通过申请获得负责人权限。
5. 审核通过后，成员刷新“我的项目”即可进入小组。有材料和编码规则时，成员可以为本人快速开始；参与多人分工时，由负责人另行安排任务，不会自动把新成员插入已有轮次。

邀请码表只保存随机20位代码的摘要；原码暂存在负责人的会话中，首次显示后移除。页面不缓存原码，研究导出和操作日志不包含原码。遗失时生成新码，旧码立即失效；停用或过期不会退出已有成员，此前已提交的申请仍可审核。申请提交与审核使用项目事务和版本检查，重复操作不重复创建成员。

已有账号无需重新注册；原密码、原项目与原编码记录不改。负责人仍可直接添加账号；只有这种初始账号首次登录需要改密。每个已登录用户仍可创建自己的独立项目，成为该项目负责人；不会获得其他项目的权限。

`PLATFORM_ALLOW_REGISTRATION=1` 默认允许自行注册；如后台不需要新账号，在 `.env` 设置为0并重启。该设置不会阻止已有账号登录和申请加入。注册按来源IP限制为每15分钟20次提交，加入按IP与账号限制为30次；登录原有限流保留。这是单进程额外保护，不是公网反滥用系统。当前无邮件验证、邮件找回密码或自动通知；申请状态需刷新查看。只在可信局域网试用，正式敏感数据仍需HTTPS。

## 数据库与质量边界

默认SQLite数据库在服务电脑 `runtime/platform.sqlite3`，使用WAL、FULL持久化和IMMEDIATE事务，所有成员通过后台访问，**不要把数据库放到网络共享盘**。该配置针对小型课题组；更大并发、正式长期部署建议PostgreSQL。

已提供PostgreSQL适配：复制 `.env.example` 为 `.env`，填写 `DATABASE_URL`，在新的空数据库执行迁移。此操作不会自动把旧SQLite资料转入PostgreSQL；迁移已有资料要另行导出/加载、核对和备份。具体测试范围见 `docs/验收说明.md`，不将本机多会话测试表述为真实多台电脑测试。

## 备份和恢复

运行 `.\.venv\Scripts\python.exe -X utf8 manage.py backup`，在 `backups/` 创建经过完整性检查的在线SQLite快照（含账号密码哈希，不含服务器密钥）。这是手动备份，首版未自动安排定时备份。请同时妥善保管 `runtime/secret.key` / `.env`，不要上传。

恢复时停止所有平台进程，先将当前数据库和WAL/SHM文件整体备份。使用已验证的数据库备份作为新的 `runtime/platform.sqlite3`，不要保留旧WAL/SHM文件与新数据库混用；由技术人员在测试目录先验证恢复、账号、记录数量和登录后再用于正式服务。**不要运行中直接覆盖数据库。** PostgreSQL使用 `pg_dump` / `pg_restore` 并实际验证。

项目ZIP是研究档案，不是完整服务器备份，也不含密码。首版还没有ZIP一键恢复功能。备份含敏感材料，建议加密并在另一设备保存。

## 开发和测试

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py test coding
node --test tests/frontend.test.cjs tests/navigation.test.cjs tests/file_tools.test.cjs tests/workflow.test.cjs
```

目录：`config/`配置；`coding/`业务与测试；`templates/`中文界面；`static/`样式与交互；`examples/`纯虚构示例；`docs/`说明；`.vscode/`调试配置。

前端测试需要Node，仅用于开发，不影响平台运行。实HTTP检查位于 `tests/live_http.py`、`tests/accounts_http.py`、`tests/simple_import_http.py` 和 `tests/workflow_http.py`，只针对127.0.0.1:8001的独立虚构测试数据库；测试会话和CSRF Cookie名称也与正式平台分开，避免同主机不同端口的会话互相覆盖。简化导入与快速编码的HTTP检查需先用 `config.ui_test_settings` 准备并启动独立测试服务，再在源码目录分别运行 `python -m tests.simple_import_http`、`python -m tests.workflow_http`；脚本仅创建虚构账号、材料和规则，不读取研究数据库。不要把测试账号、测试服务器或测试数据当作正式研究项目。GitHub自动检查已包含后台和保存交互测试，尚未包含自动浏览器端到端测试。

VS Code的“开发调试”也使用受实例锁保护的入口。先停止正常后台再按F5，代码更改后重新启动调试；不会同时开第二个8000端口后台。该调试配置使用当前数据库，有真实材料时必须先备份并另设隔离开发环境，不在正式研究服务中边调试边修改。

## 技术依据

本项目采用[Django 5.2 LTS](https://www.djangoproject.com/download/)与[WSGI部署](https://docs.djangoproject.com/en/5.2/howto/deployment/wsgi/)，业务流程依据同目录的《AI辅助编码.pdf》人工流程。该PDF及真实资料不随源码复制。账号、项目、独立编码和协商规则由本项目实现，不依赖AI或外部服务。

Excel导入先使用 [defusedxml](https://pypi.org/project/defusedxml/) 检查XML内容，拒绝DTD和实体声明，再解析表格；原始Excel公式只作为文字保存，不执行。文件大小、行列数和解压量均有限制。
编码本文字PDF使用固定版本[pypdf](https://pypi.org/project/pypdf/6.19.0/)在有时间和内存上限的本地子进程中提取文字；不提供OCR。解析限制见[pypdf文字提取说明](https://github.com/py-pdf/pypdf/blob/main/docs/user/extract-text.md)。Word文件直接读取受限的OOXML，不运行宏或读取外部链接。
