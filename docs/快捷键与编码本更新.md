# 快捷键与编码本更新

## 用键盘选择代码

| 默认按键 | 作用 |
| --- | --- |
| Alt+Q | 进入快捷编码模式，打开主代码选择框 |
| 1 / 2 | 模式内切换主代码 / 次代码；先选主代码，次代码可留空 |
| Alt+F | 保存草稿 |
| Alt+G | 确认并下一条 |
| W / S | 列表内向上 / 向下移动，不控制整页 |
| Enter | 列表内选定代码，再按一次确认并下一条，必须已有主代码 |
| Alt+Enter | 先提示可填写跳过原因；再按一次保存草稿并跳过 |
| Alt+X | 退出快捷编码模式，不改变原选择 |

按一次Alt+Q进入模式，默认聚焦主代码列表。按1切主代码，按2切次代码；W/S移动，Enter选定。选定后再按一次Enter确认并下一条，必须有主代码，次代码可以留空。平台先等待草稿保存成功再提交，不会把键盘长按当作连续提交。下一条自动打开主代码，不需要再次按Alt+Q。Alt+F保存草稿，Alt+G仍可确认并下一条。

选定后选码框保持显示。拖动标题栏移动位置，拖动右下角调大小，点击“复位”回到默认布局；布局在当前账号、轮次和标签页内延续到下一条。代码名称完整换行，长定义可展开。改选、搜索、切换主次或收起后，之前的待确认状态取消，需要重新选定再确认，避免误提交。

模式仅在当前标签页、当前账号和同一编码批次内延续，不影响其他人的设置，也不会在只读记录上自动选码或提交。Alt+X退出；Esc和“收起”只收起窗口，不退出模式。鼠标仍可选码、写备注或查看材料，不会关掉模式。关闭标签页会结束本标签页的模式。浏览器无法使用会话存储时，仍可在本页手动编码，跨页模式不会延续。

鼠标查看材料或选择代码后，直接按W/S即可继续操作当前主代码或次代码列表；即使选择框已收起，也会重新打开。1/2仍可切换主次代码，无需重复按Alt+Q。鼠标输入备注或搜索时，W/S和1/2保留为正常文字；输入完成后点击材料或列表即可继续快捷选择。

跳过时，第一次Alt+Enter高亮备注区，可写原因，也可不写。再次Alt+Enter或点击“保存并跳过”后，平台保存当前草稿与历史再进入下一条，不标记为完成，也不勾选“无适用代码”。不想跳过可点“继续编码”。跳过后按材料顺序找后面的未提交记录，末尾回到前面的未提交记录；没有其他未提交记录时进入进度页，当前条仍是草稿。

快捷模式中点击其他页面，如果还有未确认保存的修改，会提示“保存并离开”或“留在当前页”。保存的是当前编码草稿和修改历史，不会导出文件；保存失败会留在原页。已保存内容无需反复确认。浏览器本身的刷新或关闭仍可能显示未保存提醒。

需要搜索时点击搜索框，输入代码标识、名称或定义里的关键词；此时W/S作为文字输入，不会误切换代码。搜索后按Tab回到列表即可继续用W/S，或直接按Enter选定结果。方向键、Home和End仍可用。

进入“使用帮助”，在“快捷编码按键设置”点击按键框，按下想用的组合键，再点击“保存快捷键”。全部11项直接显示，包含进入模式、主次代码切换、上下选择、选定、保存、确认、跳过和退出。“选定代码 / 再按确认下一条”使用同一个自定义键，第一次选定，第二次确认，仍要求已有主代码，次代码可空。设置按账号保存在当前浏览器，不会影响其他人；换浏览器或清除网站数据后需要重设。重复按键和常见浏览器快捷键会提示冲突；可点击“恢复默认”。

原来保存过的四个个人快捷键会保留，不会强行替换成新默认值。想使用单手方案时点击“恢复默认”即可。如果旧组合与新增选择框操作冲突，会保留旧组合并提示补设冲突项；补设之前仍可用方向键、Enter和Esc。

输入中文时不会把正在组词的回车当作提交。草稿自动保存期间仍可继续选码，选择框不会因此收起；确认提交、只读、冲突或拆分时，快捷键不能绕过页面原有的限制。普通链接和功能按钮上的Enter保留原本操作，不会误当作编码确认。

### 复核标记和发言信息

“未判断／已确认／需复核”表示平台中的判断与疑点情况，不表示草稿是否已提交，也不等于协商定稿。不能稳定判断时勾选“需复核”并写备注；没有疑点的已有判断显示“已确认”。原材料的 `uncertain`、`yes`、`no` 保持原样，不会自动转成这些状态。

当前单元与前后文可显示原材料中的发言者、身份、角色、时间和引用。导入时可选对应列，已有材料由负责人或复核者在“调整发言信息显示”中修改；设置不影响原文、已有编码或快捷键。学生和AI发言均可编码，不自动清洗、不根据正文推断身份、接收者或代码。

## 拆分、撤回与开始入口

快捷模式内仍可点“拆分单元”，连续选择文字并查看预览。预览时暂时收起选码框，不能误按快捷键提交下一条；取消后恢复选码。确认后，新片段自动继续快捷模式，不需要重新按Alt+Q。默认只有Alt+X退出；换过退出键则使用自己的设置。

拆分预览中的“撤销本次选区”只撤销最近一次文字选择。确认后如果发现拆分错误，在任一片段点“撤回本次拆分”，确认恢复原句。当前未保存判断会先保存；片段、代码和备注留在历史中，进度和常规导出重新以恢复的原句为准。嵌套拆分可逐层撤回。协商、归档或片段被其他窗口更改时不能强行撤回，需刷新核对。

原句的原判断和状态保留；如果拆分后批次同步过新编码规则，恢复的原句作为草稿重新核对，不自动视作按新规则提交。多人重新拆到相同边界时保持共同单元标识，原判断在修改历史中保留，不改其他人的答案。

项目概览、材料、编码规则和侧栏的“开始 / 继续编码”使用同一检查：两类资源都没有或缺材料时先导入材料；有材料但没有当前编码规则时补充编码本；两类齐备后才能创建或继续任务。普通成员没有导入权限时，会提示联系负责人，不会因此获得上传权限。

项目内进入帮助或快捷键设置，会保留该项目的完整侧栏。点击“我的项目”或“加入小组”后回到三项全局导航；未进入项目时的帮助不会扩充导航。左侧导航和右侧页面的鼠标滚动互不带动。

## 直接更新项目的编码本

每个项目只有一份当前编码本。负责人或复核者进入“编码规则”：可编辑时直接添加或编辑代码；已经用于编码时，先点“更新编码本”，再在原规则基础上修改，无需重新上传文件。

系统自动保留修改前的规则。它们放在“修改历史”中供查看，不作为多份并列编码本。新开始的任务使用当前编码本。

### 已开始的任务要不要跟着改

由你决定。打开“将当前规则用于已有编码任务”，勾选需要同步的批次，阅读确认项，再点击“更新所选批次”。不勾选、不执行同步，旧任务就保持原样。

同步后：

- 所选批次保留原标签、备注及原始时间、组别等材料信息。
- 已提交记录退回草稿，成员按新规则核对后重新提交；旧判断仍可追溯。
- 成员已打开的旧工作台需要刷新后继续，避免旧页面覆盖新规则。
- 已在协商或已归档的批次不在同步范围内。

如果删除的代码已被所选批次使用，平台会阻止同步，不会猜测该换成哪个代码，也不会丢弃旧标签。可保留该代码、改写定义，或保留旧批次并另开新一轮编码。旧数据没有可靠对应关系时也会要求另开任务。

修改后的标签仍需人工核对。系统不会自动重新判断，也不会把按新规则复核的数据假装成一轮从未接触过样本的独立盲评。

## 导出当前编码

在“导出中心”可随时按原有权限筛选、指定数量或勾选要导出的单元，不必等全部任务完成。默认“原材料＋平台结果”保留左侧原表字段，在右侧追加 `平台_` 结果；拆分的每个当前片段各占一行，完整原句和其他原始信息仍保留。多来源分别输出并打包为ZIP，上传原件不被覆盖；“完整平台数据”样式仍可选，选行范围和权限不变。

XLSX表头无填色，保留普通单元格样式、数值与日期类型、列宽和行高，但不承诺复杂工作簿完整保真，公式不执行。原始 `uncertain` 值不转换；平台中文复核标记独立追加。详见[快速上手：保存成果和备份](快速上手.md#6-保存成果和备份)。
