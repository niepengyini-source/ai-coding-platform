## 自己怎样开始

1. 打开已经加入的项目。项目中要先有材料、有效编码单元和至少一条编码规则。
2. 点击“快速开始编码”。确认所选编码本版本；默认选择最新的有代码版本，可以自行更换。
3. 点击“开始本人的编码”，进入工作台，选择代码并写备注。

不需要先选择编码员、抽样数量或分工方式，也不需要单独点击规则冻结。负责人、复核者和编码员都能为自己开始；只读成员不能编码。

平台会为你保留一个个人批次，固定所选规则版本和此刻全部有效单元，按原文顺序排列。这个批次用于记录“谁在什么时候、依据哪版规则、编码哪些材料”，不是要求你另外做一次任务安排。

重复点击会打开同一规则版本下自己尚未完成的批次，不重复创建。开始后新导入的材料不会悄悄插入旧批次；需要编码新材料或再次编码时，先完成旧批次，再开始新的批次。规则有变化则建立新版本，不覆盖旧规则和旧答案。

## 什么时候安排多人任务

需要分工、抽样、部分双人复核，或者开展独立一致性评估时，负责人或复核者使用“安排编码任务”。原来的培训、独立试编码、正式编码流程保留。

“快速开始”只给本人生成编码，不为其他人分配任务，也不会自动把每个成员的个人批次合成一轮双人一致性报告。研究中需要同一批材料的独立比较时，请事先安排多人轮次。

## 怎样看进度

点击项目左侧的“编码进度”。

| 项目 | 表示什么 |
| --- | --- |
| 编码总条数 | 本人在这个项目里所有批次的编码任务数 |
| 已提交 | 已点击提交并锁定的记录 |
| 已保存草稿 | 保存过，但还没有提交的记录 |
| 尚未开始 | 尚无本人保存记录的任务 |
| 提交进度 | 已提交条数 ÷ 总条数 |

草稿保存成功不等于编码完成。退回修改后，这条记录从“已提交”回到“已保存草稿”；再次提交后才恢复完成计数。

汇总和本页每10秒更新一次。后台暂时不可达时保留最后一次数字，不把网络失败显示成0。新增批次或成员需要刷新页面。各批次、成员列表都有分页。

负责人和复核者可看团队及各成员的数量，普通成员只看自己的进度。这里不展示他人的代码或备注。同一单元由两人编码，或在两个批次重复编码，会分别计数，不是去重后的材料量。

## 怎样搜索以前的编码

点击“我的编码历史”。这里仅显示本人保存过的记录，没保存的空任务不会混进来。

日常查找用“快速搜索”：输入原文片段、备注关键词、主代码、来源文件名或批次名，查包含这些词的记录。“精确搜索”要求某个字段的完整内容匹配，例如主代码标识 `PLAN`；输入半句原文不会匹配完整的一句。

需要更准确时，展开“精确条件”，按单元编号、编码记录编号、主代码完整标识或名称、完整文件名、批次、规则版本、状态、不确定标记、开始方式筛选。多个条件一起填，就查同时满足这些条件的记录。数字关键词可匹配两种编号；想避免混淆，使用对应的编号字段。

可以选“今天”“近7天”“近30天”，也可填写开始和结束时间。时间使用北京时间，精确到分钟，结束时间包含该分钟；填自定义时间后，以自定义范围为准。开始晚于结束或时间格式错误时会提示，不会偷偷返回全部数据。

时间范围查的是当前记录的**最后保存时间**。一条旧记录今天又修改，最后保存时间就变为今天；想看之前的具体答案和保存时间，进入该条记录的“完整内容与修改历史”。这不是按历史上的每一次保存事件筛选全项目的页面。

主代码可用于关键词和精确条件查询；次代码在结果中展示，目前没有单独的次代码搜索条件。原表中的任意附加字段也不是这个页面的通用搜索范围。

## 怎样快捷修改

- 草稿：点击“修改”，直接打开原工作台的原单元，不需要翻页寻找。
- 个人快速编码已提交，且本批尚未归档：点击“退回并修改”，写明原因，再进入修改。原答案、原因和每次保存前后结果都会保留。
- 多人任务已提交：由负责人或复核者退回，编码员不能自行绕过提交锁定。
- 已开放协商或已归档：保持只读。是否重开协商中的多人轮次由负责人判断，重开后不能再称为盲法独立编码；归档后继续研究则建立新批次。

修改仍使用原批次的规则版本，不把新规则套到旧记录上。两个窗口同时修改时会检查保存版本；旧页面不能覆盖新答案。看到“已保存”后再离开，退回本身不会替你提交新判断。

## 怎样完成和导出

全部个人记录提交后，在工作台点击“完成并归档本批”。归档后不可直接改写。平台不会为此生成多人协商结论或一致性报告。

在“导出中心”选“我的独立编码”，再选批次和Excel、CSV、TSV或JSON格式；可自定义字段、列名和顺序。个人批次归档后，项目ZIP会把这些答案放进个人编码目录，保留规则、来源和日志，不冒充多人最终定稿数据。

所有个人批次和多人轮次都归档后，负责人或复核者才能下载完整项目研究档案。研究ZIP不是服务器恢复备份；备份方法仍按README操作。
