# 第一次怎样使用

第一阶段先做好人工编码，不需要连接AI。只需要一台电脑运行后台，其他成员在浏览器中登录。每个人使用自己的账号，不共用负责人的账号。

## 1. 打开平台

在源码文件夹双击 `start.cmd`。看到启动地址后，在浏览器打开 `http://127.0.0.1:8000`。后台已经运行时直接打开网页，不再启动一次。

首次用户名是 `owner`。初始密码在服务电脑的 `runtime/首次登录信息.txt`。第一次登录后由你自己设置新密码，初始密码不要发到公开群、写进源码或上传GitHub。

其他电脑使用启动窗口显示的局域网地址。主机关闭、休眠、断网时别人不能访问；确认保存过的记录不会因此删除。

页面左上方统一有“返回上一页”。它回到刚才浏览的页面，并保留搜索和分页条件；直接打开的页面会返回项目概览或“我的项目”。已在起始页时显示“已在首页”。编码还没确认保存时，点击返回会留在当前页并提示，请先确认“已保存”再点击。返回不会自动提交编码或退出账号。首次登录需要设置密码时，必须先完成设置。

### 同伴怎样加入你的小组

1. 你先创建编码项目，进入“项目成员”，点击“生成新邀请码”，复制本次显示的邀请码。默认7天有效；不要把邀请码公开发布。
2. 把平台的局域网地址和邀请码给同伴。同伴打开登录页，点击“创建自己的账号”，自己填用户名和密码，不需要你代设密码。
3. 同伴登录后点击“加入小组”，粘贴邀请码，说明自己的姓名或分工，再提交申请。
4. 你回到“项目成员”，点击“刷新申请”，核对身份，选择权限并点击“同意加入”。通常选择“编码员”；审核工作的人选择“复核者”。
5. 同伴刷新“我的项目”，就能进入这个项目。你再安排编码任务，成员才能在对应工作台填写自己的答案。

等待审核时不能查看项目材料。邀请码丢失、到期或传错人时可以生成新码或停用；不会删掉已有成员和编码记录。账号在这个后台通用，一个人可以加入多个项目，但不能看到未加入项目的数据。已有账号不用再次注册。

## 2. 先用示例走一遍

1. 点击“创建项目”。写清这批材料要研究什么，不必先填实验条件或组别。
2. 打开“导入材料”，选择源码中的 `examples/sample.csv`。它是虚构访谈，不是真实研究数据。
3. 在预览中把 `text` 选为文本列，把 `interview_id` 选为上下文分组列。其余列会保留，不必另建表复制。
4. 在“材料与编码单元”阅读文本。一条记录先作为一个单元；包含两个意义时可以切分。排除或切分都要写理由，原文仍保留。
5. 在“编码本与版本”创建你要练习的代码。至少写代码标识、名称和定义，再补适用条件、排除条件、正例、反例和边界例。示例数据没有标准答案，不要把随意练习的定义直接用于论文。
   已有文件时可点击“导入编码本”：上传表格或带明确规则字段的文档，对应字段、检查完整预览，再确认使用。导入页面有模板；冻结旧版本不覆盖，安排新任务时选择导入后的版本。
6. 在“项目成员”生成邀请码，让另一位编码员自行注册并申请加入，核对身份后同意。自己设置的密码不必再改一次；由负责人代建的初始账号首次登录仍需改密。
7. 点击“安排编码任务”。初次可选“培训练习”、两位编码员、单元数0、每位编码员编码同一批单元。轮次会固定编码本和单元，不能一边编码一边偷偷改规则。
8. 各人登录自己的账号，在工作台选择代码、写备注，确认“已保存”后再切换。练习结束后，可用新轮次做独立试编码。

你的真实 `messages.csv` 也按同样方式导入：文本列通常选 `content`，上下文分组列选能区分连续对话的字段。平台没有规定必须叫 `condition`、`group_id` 或其他名称。

不要把不同时间或不同对话中同名的小组混在一起。如果一个分组字段不足以区分材料，先在文件副本中整理唯一会话编号，或分成不同文件导入。原始文件另行保留。

## 3. 工作台究竟填什么

| 页面内容 | 你要做什么 | 为什么要填 |
| --- | --- | --- |
| 主代码 | 选择最能概括当前单元主要含义的代码 | 让原文变成可以比较、分析的类别 |
| 次代码 | 确有另一种含义且不能合理切分时选择；否则留空 | 保留一段话同时承担多个功能的情况 |
| 不确定／需要讨论 | 不能稳定判断时勾选，并写清原因 | 把真正需要协商的样本标出来，不凭猜测硬选 |
| 明确没有适用代码 | 确认没有任何现有代码适用时勾选，不再选标签 | 区分“判断后没有代码”和“忘记填” |
| 编码备注 | 写判断依据、上下文条件或疑点；可中文或英文 | 以后能说明为什么这样编码，而不只有一个标签 |

代码标识和含义由项目编码本决定。PDF中的实验代码是示例，不是平台通用的强制选项。不确定时也不用强行选择某个固定的“无法判断”代码。

主代码不能同时勾选为次代码。单标签版本不填写次代码。草稿编辑后会自动保存；“提交并锁定”表示这条独立判断完成，之后不能直接改写。

如果保存提示版本冲突，页面会保留你的输入，但不允许继续覆盖。先复制自己未保存的备注，再刷新查看最新内容；必要时联系负责人。网络异常时不要关闭页面，等待恢复并重试，直到明确显示保存成功。

## 4. 从独立编码到定稿

独立试编码和正式编码期间，平台隐藏别人答案。请不要在平台外交换具体样本答案。进度只显示数量，不显示他人选择。

全部编码员提交后，负责人在工作台打开“负责人操作”，进入协商。平台不会因为自己觉得进度够了就提前公开答案。

先计算一致性报告，使用的是协商前的独立答案。再打开“分歧与疑点清单”，按原文、上下文、规则定义来讨论；逐条保存最终代码和依据。协商结论不会覆盖独立判断。

“分歧或疑点”只列出系统能确定的标签差异和不确定标记；上下文不足、定义重叠等具体原因需要你们判断并记录。即使独立标签一致，也要在“尚未定稿”里确认最终结果。

如果规则不清楚，复制编码本建立新版本，再开新轮次。第二轮可以在“指定单元编号”中填写旧分歧样本和新样本编号，逗号、空格、换行都可以；单元数0表示全部指定单元。样本构成由你的研究方案决定，不强制某个比例。

旧样本曾经公开讨论过，重新编码属于边界复测，不能当作完全陌生的新样本。报告会提示抽样历史；平台也不能保证成员在平台外从未看过答案。新样本与复测样本应分别说明来源和目的。

## 5. 怎样理解报告

先看有效配对数，再看一致率和κ／α，不能只看一个数字。部分单人分工的单元没有配对对象，不用于双人一致性计算。

多标签时，标签集合一致、主代码一致、次代码一致是三件不同的事；主次互换仍然要讨论。次代码一致率包含两人都没有次代码的情况，不表示稀有次代码一定识别得好。

一级维度根据你在编码本里明确设置的“上级代码”计算，不根据A1、A2这样的名称猜测。没有层级就不计算这一项。

不确定记录不进入有效配对指标，但会单独统计。报告中的“—”可能是没有足够样本或没有类别变化，不代表零分或满分。平台不会直接宣布“编码质量合格”。

## 6. 保存成果和备份

所有单元完成有效最终结论后，负责人归档轮次，再到“导出中心”选择最终定稿数据。可选Excel、CSV、TSV、JSON；编码本另可导出Word。所有轮次定稿后才能下载完整项目ZIP。

“导出中心”也能导出材料、编码本、自己的独立答案、开放后的全员答案及分歧清单。默认导出全部字段；需要时勾选字段、改列名和顺序，CSV还可选分隔符、UTF-8或GB18030。操作不会修改原始数据。详细步骤见[导入编码本与自定义导出](导入编码本与自定义导出.md)。

原始附加字段会导出为 `meta_原表头`，例如 `meta_message_id`；原始字段字典也保存在 `metadata_json`。`unit_id` 是平台编码单元编号，不能与原始 `message_id` 混为一谈；拆分后一个原始消息可对应多个单元。

CSV/TSV备注和文本如果以公式符号开头，导出会加安全前缀，避免软件把它当公式执行。Excel按文字写入，JSON保留原文。需要完整研究档案时仍下载项目ZIP，普通导出不是服务器备份。

项目ZIP用于研究留档，不是整个平台的恢复备份。手动数据库备份方法见README。平台首版没有自动定时备份，请明确由谁、多久备份一次。

以后上传GitHub只上传 `ai-coding-platform` 这个源码文件夹。不要上传 `runtime`、`.env`、数据库、备份、登录信息，或上一级文件夹里的论文和真实编码数据。
