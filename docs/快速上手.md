# 第一次怎样使用

第一阶段先做好人工编码，不需要连接AI。只需要一台电脑运行后台，其他成员在浏览器中登录。每个人使用自己的账号，不共用负责人的账号。

首次准备项目时，按页面中的“导入材料 → 准备编码本 → 确认并开始”操作。材料确认导入后，点击蓝色“下一步：准备编码本”；编码本确认导入或手动添加代码后，点击“下一步：确认并开始”。每一步显示当前进度，上传预览本身不算导入完成。编码本预览顶部的“下一步：确认导入”可直接定位到确认区，核对并勾选后再保存。已有编码任务仍按原指引继续。

## 1. 打开平台

在源码文件夹双击 `start.cmd`。看到启动地址后，在浏览器打开 `http://127.0.0.1:8000`。后台已经运行时直接打开网页，不再启动一次。

首次用户名是 `owner`。初始密码在服务电脑的 `runtime/首次登录信息.txt`。第一次登录后由你自己设置新密码，初始密码不要发到公开群、写进源码或上传GitHub。

其他电脑使用启动窗口显示的局域网地址。主机关闭、休眠、断网时别人不能访问；确认保存过的记录不会因此删除。

登录后先选择“我的项目”或“加入小组”。“我的项目”包含自建和已加入的小组项目，并显示创建时间和最后更新；没有项目时，点击中间的“创建项目”。登录、入口与项目列表不显示侧栏，后续操作页保留侧栏及“返回上一页”。返回会保留搜索和分页条件；编码还没确认保存时会提示留在当前页，不会自动提交或退出。首次需要设置密码时仍须先完成设置。

### 同伴怎样加入你的小组

1. 你先创建编码项目，点击项目概览右上方的“邀请成员”，按“生成邀请码 → 成员加入与审核 → 开始协作”操作。原“项目成员”入口仍可使用。默认7天有效；不要把邀请码公开发布。
2. 把平台的局域网地址和邀请码给同伴。同伴打开登录页，点击“创建账号”，自己填用户名和密码，不需要你代设密码。
3. 同伴登录后点击“加入小组”，粘贴邀请码，说明自己的姓名或分工，再提交申请。
4. 你在邀请指引中点击“刷新申请”，核对身份，选择权限并点击“同意加入”。通常选择“编码员”；审核工作的人选择“复核者”。
5. 同伴刷新“我的项目”，就能进入这个项目。负责人可以点击“开始／继续编码”进入自己的工作，并通过“查看成员进度”核对每人的已提交／总任务数；工作台顶部也有“成员进度”。加入成员不会自动创建任务，需要多人分工时再选择“安排团队任务”。

等待审核时不能查看项目材料。邀请码丢失、到期或传错人时可以生成新码或停用；不会删掉已有成员和编码记录。账号在这个后台通用，一个人可以加入多个项目，但不能看到未加入项目的数据。已有账号不用再次注册。

## 2. 先用示例走一遍

1. 点击“创建项目”。写清这批材料要研究什么，不必先填实验条件或组别。
2. 在项目概览的“导入材料”选择源码中的 `examples/sample.csv`，点击“上传并预览”。它是虚构访谈，不是真实研究数据。这里也支持XLSX和TXT；只有负责人和复核者可以导入。
3. 在预览中把 `text` 选为文本列，把 `interview_id` 选为上下文分组列，核对后点击“确认导入”。其余列会保留，不必另建表复制。Excel有多张表时先选对应工作表。
4. 在“材料”阅读文本。一条非空记录先作为一个有效编码单元，“有效”不代表已经编码完成。材料页的排除、合并或切分需写理由，只影响以后安排的任务；编码中拆分本人任务的方法见下文。
5. 在“编码规则”创建你要练习的代码。至少写代码标识、名称和定义，再补适用条件、排除条件、正例、反例和边界例。示例数据没有标准答案，不要把随意练习的定义直接用于论文。
   已有文件时可点击“导入编码本”：上传表格或带明确规则字段的文档，核对自动对应的预览，再确认使用。只有识别不明确时才需要手动选列，其他选项默认折叠。每个项目使用一份当前编码本，后续直接点击“更新编码本”增改，旧规则作为修改历史保留。
6. 在“项目成员”生成邀请码，让另一位编码员自行注册并申请加入，核对身份后同意。自己设置的密码不必再改一次；由负责人代建的初始账号首次登录仍需改密。
7. 点击“开始 / 继续编码”。已有任务会直接打开；第一次开始时核对规则版本，确认后进入工作台。不需要先安排任务，也不需要另点冻结。多人分工时，在“项目管理”中选择“安排编码任务”。
8. 各人登录自己的账号，在工作台选择代码、写备注，确认“已保存”后再切换。练习结束后，可用新轮次做独立试编码。

你的真实 `messages.csv` 也按同样方式导入：文本列通常选 `content`，上下文分组列选能区分连续对话的字段。平台没有规定必须叫 `condition`、`group_id` 或其他名称。

导入预览中的发言信息为可选设置：可对应发言者、身份、角色、时间、消息编号、引用和明确接收者；没有对应列就留空。已有材料可由负责人或复核者在“调整发言信息显示”中修改。工作台当前单元和前后文使用同一设置，完整原始附加信息仍可展开查看。平台不根据姓名或正文猜身份、接收者或编码，引用也不等于接收者；学生与AI发言均保留供人工编码，本阶段不自动清洗材料。

不要把不同时间或不同对话中同名的小组混在一起。如果一个分组字段不足以区分材料，先在文件副本中整理唯一会话编号，或分成不同文件导入。原始文件另行保留。

### 怎样安排编码任务

按“安排什么工作 → 谁来编码 → 选哪些材料”填写。默认勾选负责人，可取消；“本轮共选多少条”是材料总数，不是每位成员的数量。高级设置中的随机种子和分层抽样通常不用修改。

- **连续选取**：输入从材料第几条开始、共选多少条；填0表示从起点选到最后。
- **手动选择**：可输入 `3、8、15-30、47` 等不连续序号和区间，或按关键词、来源文件、原始附加信息筛选，再选择全部匹配。跨页保留已选项，可查看和移除，重复单元只选一次，一次最多10000条。
- **随机抽取**：由系统抽取指定数量，填0表示使用全部有效材料。相同材料、种子和设置可以复现抽样。

这里的顺序号从本项目有效材料的第1条开始，不是全平台的系统编号。点击“预览任务安排”核对材料及各成员数量，再点“确认分配任务”；返回修改不会丢失选集。预览期间材料、规则或成员变化时需要重新核对，不会悄悄改动已经分配的任务。负责人参与本轮时，确认后直接进入自己的工作台；只管理而不参与时进入进度页。

## 3. 工作台究竟填什么

| 页面内容 | 你要做什么 | 为什么要填 |
| --- | --- | --- |
| 主代码 | 选择最能概括当前单元主要含义的代码 | 让原文变成可以比较、分析的类别 |
| 次代码 | 主代码＋次代码模式下可选一个，不与主代码相同；无需要时留空 | 保留一段话同时承担另一种功能的情况 |
| 需复核 | 不能稳定判断时勾选，并写清原因 | 把真正需要协商的样本标出来，不凭猜测硬选 |
| 明确没有适用代码 | 确认没有任何现有代码适用时勾选，不再选标签 | 区分“判断后没有代码”和“忘记填” |
| 编码备注 | 写判断依据、上下文条件或疑点；可中文或英文 | 以后能说明为什么这样编码，而不只有一个标签 |

代码标识和含义由项目编码本决定。PDF中的实验代码是示例，不是平台通用的强制选项。不确定时也不用强行选择某个固定的“无法判断”代码。

复核标记使用中文三态：“未判断”表示尚无编码判断；“已确认”表示已有判断且未标记疑点；“需复核”表示已有判断并标记了疑点。它与草稿／已提交、协商定稿是不同的状态，“已确认”不代表已提交、已定稿或研究质量合格。原材料中名为 `uncertain` 的列及其 `yes`／`no` 等值保持原样，不自动转换成平台复核标记。

工作台里点击代码卡片选择主代码，同时查看定义；条件和例子按需展开，也可输入关键词搜索。主代码和一个次代码可以一起保留，次代码是单选，可点“清除”取消；单标签版本不填写次代码。草稿编辑后自动保存；点击“确认并下一条”，提交成功后才进入下一条，最后一条完成后进入进度页。

也可按一次Alt+Q进入快捷编码模式：1选主代码、2选次代码，W/S在列表内上下选择，Enter选定，再Enter确认并下一条（主代码必选，次代码可留空）。Alt+Enter先提醒可在备注写跳过原因，再次按键或点“保存并跳过”后保留草稿，不计完成。下一条自动打开主代码，Alt+X退出模式；鼠标选码、写备注不会退出。离开页面有未保存内容时会提示保存。按键可在“使用帮助”中修改；已有个人设置的用户可点击“恢复默认”使用这组按键。详见[快捷键与编码本更新](快捷键与编码本更新.md)。

### 编码过程中拆分材料

1. 点击“拆分单元”，在当前文字中拖选要单独编码的部分。
2. 松开鼠标即可看到编号预览。还需要细分时继续选其他部分；选错可点“撤销上次”，不拆了可点“取消”。
3. 核对将生成的条数，再点击“确认拆分并编码（N条）”。平台先保存当前编辑，再打开选中的新片段。
4. 为每个片段选择代码、保存或提交。片段仍可继续拆分。

选在开头或结尾通常得到两条，选在中间通常得到三条；连续选择可得到更多条，一次最多50条。一个字的单元无需拆分。预览中包含全部原文，不丢字、不重复；确认前不会修改数据库。

个人快速批次和多人任务都支持拆分本人记录，包括已保存、已提交的记录，但轮次必须仍在编码中。正在提交、网络未确认或保存冲突时，先完成同步再拆分；锁定和归档后不能拆分。

新片段不继承旧标签，需要分别判断。原材料、拆分前的代码与备注只读保留，在新片段的“来源与附加信息”中点击“查看拆分前的编码”即可查看。拆分不改其他成员的任务，也不改变以后分配的共享材料。

多人需要统一拆分边界时先商定方法；边界不同的片段不会被平台强行当成同一单元比较。

未归档的个人快速编码可从历史入口写明理由后退回修改，多人任务仍需负责人或复核者退回。已有判断不会因拆分被删除。

如果保存提示版本冲突，页面会保留你的输入，但不允许继续覆盖。先复制自己未保存的备注，再刷新查看最新内容；必要时联系负责人。网络异常时不要关闭页面，等待恢复并重试，直到明确显示保存成功。

### 查看进度，找回以前的编码

项目概览中的“编码进度”（也可从左侧“项目管理”打开）显示自己的总条数、已提交、草稿和未开始数量。完成比例只统计已提交；负责人和复核者还可看团队数量，不会因此看到别人答案。拆分后只统计当前片段，不重复计算旧单元；新片段尚未提交时，完成比例可能下降。

“历史记录”可以按今天、近7天、近30天或开始/结束时间查询，也可输入关键词快速搜索。精确搜索要求完整匹配；需要查单元编号、某个主代码或批次时，展开“精确条件”组合筛选。日期按最后保存时间计算，使用北京时间，结束时间包含该分钟。

草稿点击“修改”直接进入原单元；已提交的个人快速编码点击“退回并修改”，填写原因后再改。点“查看完整内容与修改历史”可看每次保存前后的答案。全部个人编码提交后，可“完成并归档本批”；归档记录只读，不会伪造多人协商结论。详见[快速开始与编码历史](快速开始与编码历史.md)。

## 4. 从独立编码到定稿

独立试编码和正式编码期间，平台隐藏别人答案。请不要在平台外交换具体样本答案。进度只显示数量，不显示他人选择。

全部编码员提交后，负责人在工作台打开“负责人操作”，进入协商。平台不会因为自己觉得进度够了就提前公开答案。

先计算一致性报告，使用的是协商前的独立答案。再打开“分歧与疑点清单”，按原文、上下文、规则定义来讨论；逐条保存最终代码和依据。协商结论不会覆盖独立判断。

“分歧或疑点”只列出系统能确定的标签差异和不确定标记；上下文不足、定义重叠等具体原因需要你们判断并记录。即使独立标签一致，也要在“尚未定稿”里确认最终结果。

如果规则不清楚，在“编码规则”点击“更新编码本”，直接修改后再开新轮次。也可以选择将当前规则用于仍在编码的旧批次：原标签保留，已提交记录退回草稿重新核对；不选择则旧批次不变。协商中和已归档批次不自动更改。第二轮可以用“手动选择”批量指定旧分歧样本和新样本，预览核对后分配。样本构成由你的研究方案决定，不强制某个比例。

旧样本曾经公开讨论过，重新编码属于边界复测，不能当作完全陌生的新样本。报告会提示抽样历史；平台也不能保证成员在平台外从未看过答案。新样本与复测样本应分别说明来源和目的。

## 5. 怎样理解报告

先看有效配对数，再看一致率和κ／α，不能只看一个数字。部分单人分工的单元没有配对对象，不用于双人一致性计算。

主代码＋次代码模式下，标签集合一致、主代码一致、次代码一致是三件不同的事；主次互换仍然要讨论。次代码一致率包含两人都没有次代码的情况，不表示稀有次代码一定识别得好。多人拆分边界不同的片段不能直接配对，解释报告时要同时看边界是否一致。

一级维度根据你在编码本里明确设置的“上级代码”计算，不根据A1、A2这样的名称猜测。没有层级就不计算这一项。

不确定记录不进入有效配对指标，但会单独统计。报告中的“—”可能是没有足够样本或没有类别变化，不代表零分或满分。平台不会直接宣布“编码质量合格”。

## 6. 保存成果和备份

不必等全部编码结束才导出。在“导出中心”选择“我的独立编码”即可保存当前有权限查看的个人结果；可按条件筛选、指定数量或勾选具体单元，只导出所选数据。全员答案仍须开放协商后才能查看；最终定稿数据仍按原有定稿条件提供，个人结果不称为协商定稿。导出不会改变任务进度、权限或归档状态。

材料和编码结果默认使用“原材料＋平台结果”：左侧保留原表字段、顺序和内容，右侧追加以 `平台_` 开头的结果字段，原有同名列不覆盖。“沿用原材料格式”可直接生成可继续使用的结果文件；涉及多个来源时按各自原表结构分别输出，再打包为ZIP，不把不同原表强行拼成一张表。下载的是新文件，平台不会覆盖上传的原件。

拆分后每个当前片段各占一行，左侧重复保留完整原句和原始时间、组别、说话人等信息，右侧给出该片段及其对应编码。拆分前的旧判断不混入当前结果，仍可在历史中追溯。导出范围只包含选中的单元，不会因为使用原表样式就额外带出整份文件的未选行、空白行或重复跳过的行。

XLSX结果表头不填色；原表普通单元格样式、数值与日期类型、列宽和所选行的行高会尽量保留。这不是复杂工作簿的完整复制：公式按文字保留，不执行；图表、合并布局、其他工作表等不承诺原样重建。需要复杂版式时请另存原工作簿作为底稿。

需要系统编号、修改追踪字段或原有字段勾选、改名与排序时，可切换“完整平台数据”。该样式中的附加字段仍使用 `meta_原表头` 和 `metadata_json`；`unit_id` 是平台编号，不等于原材料的消息编号。可选Excel、CSV、TSV、JSON，编码本另可导出Word；详细步骤见[导入编码本与自定义导出](导入编码本与自定义导出.md)。原材料的 `uncertain` 等字段不作真假解释，平台的“未判断／已确认／需复核”独立追加。

多人流程中，所有单元完成有效最终结论后，负责人可归档轮次。所有个人批次归档、多人轮次定稿归档后，才能下载完整项目ZIP；其中另保留旧记录、原材料和拆分日志。多来源结果ZIP与完整项目归档ZIP不是同一种文件。

CSV/TSV备注和文本如果以公式符号开头，导出会加安全前缀，避免软件把它当公式执行。Excel中的文本和公式样内容按文字写入，原始数值和日期保留对应类型；JSON保留原文。普通导出不是服务器备份。

项目ZIP用于研究留档，不是整个平台的恢复备份。手动数据库备份方法见README。平台首版没有自动定时备份，请明确由谁、多久备份一次。

以后上传GitHub只上传 `ai-coding-platform` 这个源码文件夹。不要上传 `runtime`、`.env`、数据库、备份、登录信息，或上一级文件夹里的论文和真实编码数据。
